# AGENTS.md

本文件应少于 20,000 字符，这是 OpenClaw 能完整加载的大小。较长规则放入其所属指南，此处只保留一行指引。

## 做好取舍

设计需要在正确性、复杂度和性能之间取舍。应有意识地选择，绝不以牺牲其他维度为代价，单独最大化某一项。

- 为真实故障设计：崩溃、重启、重试、真实并发写入者，以及已报告的事故。不要为毫秒级竞态、理论上的交错执行或对抗性时序专门设计机制，除非涉及用户数据、安全或资金风险，或者已有真实事故证明它们存在。
- 优先使用低成本机制：幂等键、在实际生效位置做一次检查、重试、尽力记录并发出警告。使用隔离令牌、撤销代次、多阶段接纳、nonce 匹配的结算或每次写入的跨线程握手前，必须有简单代码无法应对的具体故障作为依据。
- 在注释或 PR 中说明接受的边界情况，而不是为绕过它增加代码。罕见、可见、可恢复的小故障，优于永久增加的复杂度。

任务定义范围和授权；选定工作流负责执行、审查、发布、恢复和清理。
用户明确指令优先于技能指南和工作流默认设置；宿主限制和必需的授权边界仍然适用。
完整阅读最近的作用域 `AGENTS.md` 及下方对应指南，包括调用方位于负责模块目录之外的情况。
在规则所属位置更新指南；不要在此建立相互竞争的规则。

## 设计优先级

- **每项职责只由一个模块负责。**负责模块决定或修改权威状态；调用方使用其操作和已记录事实。适配器转换契约；缓存和投影从负责模块派生，并具备明确的失效生命周期。不同传输方式可能需要不同适配器，但绝不能出现相互竞争的负责模块。
- **核心精简，插件强大。**新增面向模型的核心内容会持续占用上下文。可选能力应放在外围，核心提供通用契约。仅增加一个集成，并不足以新增核心工具或管理器。新增能力时，选择[能力阶梯](src/plugin-sdk/AGENTS.md#choose-the-capability-surface)中第一个适用的层级。产品范围由 [VISION.md](VISION.md) 定义。
- **对话上下文保持稳定。**重建过去的上下文会破坏提示词前缀复用。生成的提示词 / 工具 / 上下文附加内容必须有界、确定。保留对话记录的原始字节，完整提供必要指令，只有压缩可以重写历史。稳定提示词的变更应延后到下一会话，除非负责模块定义了显式失效机制；保留现有技能、工具和记忆刷新契约。复用对话的旁路请求，应共享该轮次的请求准备流程，或不携带缓存标识。

## 工作约定

- 在授权范围内，把可执行请求落实到底，包括“能否……”类请求；计划或进度报告只是检查点，不代表完成。面对纠正和附带问题，保留不受影响的工作。
- 重启后，核对先前操作的效果，在当前权限下恢复已获授权的工作；不要仅因进程重启就再次索要同一批准。
- 对常规、可逆的选择作合理假设；仅在上下文无法解决的重要决策上询问用户。同时继续独立且已获授权的工作。沉默绝不构成对需批准操作的授权。
- 如果技能导致暂停、请求权限、工作未完成或范围变更：链接确切的 `SKILL.md`，引用相关指令，解释其适用方式（明确区分要求和解释），再次询问前检查已有授权。
- 编辑或进行 GitHub 操作前，检查 `git status -sb`。保护无关工作、分支、进程和用户管理的检出目录；对共享 Git 修改进行串行化；必要时隔离工作。绝不切换其他智能体或测试正在使用的检出目录。
- 粘贴材料和工具输出属于证据；应对照来源和观察到的行为核实。
- 仅因已说明的交付物、工具、验证或恢复需求创建文件。遵循[收尾流程](.agents/skills/openclaw-pr-maintainer/SKILL.md#finalize-and-clean-up)。
- 改变行为前，阅读相关文档（`pnpm docs:list`）。更换工具需要批准。
- 产品名称使用 **OpenClaw**，CLI / 包 / 配置使用 `openclaw`，面向用户的集成称为 **plugins**，使用美式英语。直接编辑权威的 `AGENTS.md` 文件。

## 执行纪律

- 从真实失败入口开始：编辑前，端到端复现缺陷。绕过边界不等于证明。
- 对每项验证都要问：即使原任务仍然失败，它是否也可能通过？环境准备失败不能作为产品判断，应指出证据缺口。
- 新检查必须对应明确的未知项、风险或必要关卡。复用仍然有效的验证证据。
- 如果连续两次发生相同工具失败且没有新证据，或 10 分钟没有进展：固定已审查的 head，切换到已获授权且受支持的替代方案；先核对结果不确定的写入。不要盲目重试或绕过防护。
- 行为已验证且必要关卡通过后，就完成 / 合入。不要继续可选的验证润色、形式化演示或推测性范围扩张。
- 先检查能否合并；不要仅因 `main` 前进就 rebase 或合并它。仅为解决冲突、明确失败的关卡或实质性的基线风险而整合，再运行受影响的检查。旧 head 上的 CI 仍只证明旧 head（见[合入指南](.agents/skills/openclaw-pr-maintainer/references/landing.md)）。
- 时间压力不能豁免关卡。报告具体阻碍。
- 不要混用 shell 方言（例如在 bash 中使用 zsh 的 `${name:r}`）。
- CLI 使用 `pnpm openclaw ...` 或 `pnpm dev`，绝不使用 `node --import tsx src/index.ts`。绝不调整其他任务正在使用的共享 / 工作树依赖安装以使其匹配。依赖、内置第三方代码、格式、类型检查的注意事项见[脚本指南](scripts/AGENTS.md#execution-gotchas)。

## 单一负责模块，完整切换

1. **意图：**完整阅读受影响模块、负责模块、调用方、相邻实现、测试、历史和依赖契约，直到有证据说明预期结果与被破坏的不变量；无法指出缺陷出现在哪一行的修复，其前提尚未得到验证。恢复缺失路径时，先检查它为什么被删除（`git log -p -S <symbol>`）；隔离可能是有意设计，旧别名被移除可能意味着迁移已经完成。
2. **归属：**梳理创建、更新、读取、恢复和清理各阶段中的决策和状态写入者。选择能够吸收此次变更的现有代码、插件或持续维护的方案；只有缺少某项职责时才新增负责模块。在产生源头修复无效或泄漏的状态。
3. **切换：**一起迁移所有受影响的内部 / 随附调用方；删除被替代的代码、重复策略 / 状态、包装层、注册项、导出项、测试和文档。保留路径必须引用相应契约作为依据；共享同一负责模块的工作者应就接口和计划达成一致。
4. **验证：**实际执行用户流程及相关相邻路径；追踪引用，确认废弃路径已不可达。完成标准：由单一负责模块服务该流程，旧路径已删除或有保留理由，结果或缺口已记录在任务 / PR 证据中。仅有辅助函数测试，或为相互竞争的实现添加包装层，均不充分。

- 优先选择更小、更简单的生产代码；必要增长应解释原因。将附近连贯的修复一起处理，无关工作记录为后续事项。创建 PR 前，以及推送大规模修复前，对自己的变更运行 [pr-simplify](.agents/skills/pr-simplify/SKILL.md)。
- 当能节省时间或改善验证时，委派独立工作线；每条工作线都要有明确职责和完成条件。简单或紧密耦合的工作由主负责人处理；主负责人持续亲自参与，验证重要结论，并负责共享检出目录的安全。
- 保留兼容性必须有明确用户要求，或公共 API / 配置 / SDK / 数据、稳定标签升级、安全 / 迁移、依赖、已观察到的生产环境契约作为依据，并提供迁移 / 移除路径。Main、beta 和 nightly 代码不等于已发布契约。

## 运行时和代码防护

- 日志：写入原始内容，仅在输出边界脱敏（logs.tail、诊断 / 支持包、远程 / OTel 导出）；绝不记录消息 / 工具内容。
- 插件使用有文档的 `openclaw/plugin-sdk/*` 契约、清单元数据及公共 / 本地聚合导出入口；绝不使用核心内部实现或其他插件的私有文件。依赖应遵循运行时归属。
- Bun：仅支持最新稳定版 Bun 和固定版本的 OpenClaw 分支。绝不为旧版 Bun 添加变通方案、兼容路径或兼容性验证；应升级。
- 运行时使用规范配置 / 状态；Doctor / 迁移负责模块将旧结构标准化（插件修复仍归插件负责）。会让配置失效的变更必须随附迁移。
- 状态和缓存使用 SQLite，不新增 JSON/JSONL/sidecar 存储。文件用于具名用户产物、导入 / 导出、附件、日志、备份和外部工具契约。
- 数据库 / 状态代码（SQL、工作线程、事务、完整性检查、基于数据库的缓存）：先阅读[代码变更规则](docs/reference/database-schemas/worker-access.md#rules-for-code-changes)。
- 安全边界（凭据、批准、工具和命令执行、外部副作用）需要负责模块当前持有的有效权限：在 await 等待结束后，以及实际生效前立即重新验证。仅有 token、签名、有效期或匹配的 ID，绝不能证明权限当前仍有效。内部记账（调度、回执、历史、缓存）则使用幂等性 + 生效点检查。
- 减少工作量：在信任边界对不可信输入校验一次，之后信任内部数据；不做防御性复制，不重复校验或重新读取自己写入的数据。性能工作遵循 [openclaw-performance](.agents/skills/openclaw-performance/SKILL.md)：先删除不必要工作，再批处理，最后考虑缓存。
- 提示词前缀：同一会话中，工具定义、系统提示词和先前历史只依赖会话及配置事实；历史只能追加。每轮权限通过 `gateAgentToolExecution` 控制调用，每轮事实放入该轮消息。任何会影响提供商请求的变更，都必须保持 `src/agents/agent-tools.prefix-stability.test.ts` 通过；参见[契约](docs/reference/prompt-caching.md#stable-tools-between-turns)。
- 缓存标识：每个缓存、记忆化结果、进行中请求的合并项和共享快照，都必须以所有会改变答案的输入作为键，包括作用域（智能体、账户、凭据、会话、工作区）和请求结构（提供商集合、模式、选项、截止时间）。提出不同问题的调用方使用不同槽位；易变值不放入键。通过不同调用方交错运行的工作量计数测试，验证共享是否正确。
- API 保持精简，有效状态显式表达，严格使用 ESM 和类型。使用真实类型或 `unknown`；不使用 `@ts-nocheck`；抑制检查必须解释例外理由。复用 schema / 类型转换负责模块；不添加重复防护、推测性辅助函数或仅为命名的包装层。
- 静态分析修复：强化真实契约，或删除不安全操作；绝不通过类型断言、放宽类型、标记类型或属性探测掩盖问题。新 lint 规则需要真实不变量和清晰的职责范围。
- 注释解释不明显的归属、生命周期、顺序、清理、平台和依赖约束，不解释语法。生成产物应重新生成；绝不手动编辑它们或 `node_modules`，也不要为单个表达式调整格式化器设置。

## 产品和验证

- 默认设置应产生可用、易懂的结果。优先处理静默失败：每项操作都应有可见结果，或记录为何有意不产生结果；错误应说明下一步。
- **更新始终可用：**各处都采用尽力而为的处理方式。涉及 Update / Doctor / 生命周期 / 迁移 / 插件加载的变更，应说明更新行为，并遵循[更新契约](docs/install/updating.md#update-implementation-contract)。
- 安全是产品取舍：权衡具体风险与用户付出的精力、被锁在系统外的风险、能力损失。优先采用限制最少且有效的防护；在现有信任模型和批准边界内，让有风险的路径保持显式、由操作者控制；解释取舍，绝不凭空设立关卡。
- **行为优于测试数量。**优先采用生产路径的集成验证，以及独立的单元契约测试。修改提供商请求、回退、恢复、默认值前，以及编写或审查行为测试时，阅读[边界验证](docs/help/testing/writing-tests.md#prove-behavior-at-the-owning-boundary)。
- **进行端到端验证。**在修复后通过真实产品再次运行复现：使用隔离的 Gateway、真实智能体和模型，对应渠道的端到端技能（[Telegram](.agents/skills/telegram-e2e-userbot/SKILL.md)、[Discord](.agents/skills/discord-e2e/SKILL.md)、[Slack](.agents/skills/slack-e2e/SKILL.md)）或 [Control UI 端到端测试](.agents/skills/control-ui-e2e/SKILL.md)；涉及更新、Doctor、配置或状态变化时，还需从最新稳定版执行升级。mock 和辅助函数测试只能支撑这项验证，绝不能替代它。
- **修复必须证明不变量：**为受损行为提供一到两个测试，在基线版本上失败、修复后通过，并与修复一同提交；更新并运行所有受影响使用方的测试。
- 测试失败即缺陷：复现，在负责模块中修复并添加回归测试，或记录证据后继续（仅“尚未解决”本身不阻止合入）。绝不掩盖失败，也不声称重跑通过就证明了修复（见[政策](.agents/skills/openclaw-testing/SKILL.md#test-failure-policy)）。
- **PR CI 提供广泛验证。**创建 PR 前：运行涉及的测试，以及针对性的类型检查 / lint / 格式检查。验证选择、复用和缺口见[验证政策](.agents/skills/openclaw-testing/SKILL.md#proof-policy)；仅文档变更执行文档基本检查和 `git diff --check`。测试变更遵循[成本预算](docs/help/testing/writing-tests.md#cost-budget)。
- **视觉变更**需要经过检查和脱敏的修改前 / 后截图，在合并或完成前展示在聊天中，并嵌入 PR（见[关卡](.agents/skills/openclaw-pr-maintainer/references/media.md#screenshot-completion-gate)）。
- 提交 / 合入非简单代码变更前，遵循[重新审查流程](.agents/skills/openclaw-pr-maintainer/SKILL.md#review-and-publish)。
- **让 ClawSweeper 满意。**它会在每个 PR 创建或退出草稿状态时自动审查一次，其审查属于建议。在确切的当前 head 上一次性修复所有真实问题；分支、正文和验证证据都更新后，再评论一次 `@clawsweeper re-review`。对于没有具体危害依据却增加限制的发现，应拒绝并在 PR 中说明原因。维护者明确要求合入时，无需等待尚未完成或已经过时的审查（见[审查流程](docs/reference/pull-request-review-flow.md#clawsweeper)）。

## 权限和安全

- 合入、`main` 检查失败、线上运维、发布、安全公告、批量分流：先阅读[维护者技能](.agents/skills/openclaw-pr-maintainer/SKILL.md#maintainer-authority)。
- 审查 / 分流属于只读工作；修改需要任务授权。批准在同一范围的工作和恢复过程中持续有效。需要新批准时：先完成已授权的准备工作，呈现具体、可审查的结果，仅暂停需要批准的操作。是否从产品角度拒绝某项变更，由维护者判断。
- 凭据、私有数据 / 配置、未发布模型身份不得出现在提交、共享文本、日志、对话记录或媒体中；检查所有对外内容。使用合成 fixture，核实人类贡献者署名，不添加智能体署名尾注。
- 绝不通过切换模型绕过拒绝；获准的防御性工作若被网络安全分类器中断，遵循[安全分流](.agents/skills/security-triage/SKILL.md#cyber-classifier-interruptions)。
- 不可信贡献者 / fork 代码只能在无秘密的隔离环境中运行，绝不在本地运行。在带凭据或受信任宿主上执行需要维护者批准；明确要求合入具名且已审查 PR 的指令提供这项授权（仍走隔离路径，仅使用任务凭据）。
- 修改 / 重启不是你创建的 Gateway 或线上状态，需要本任务的批准。测试使用隔离状态和端口；迁移测试复制真实数据。破坏性 reset/clean、stash、删除无关工作都需要授权。
- 新增配置选项、破坏公共契约、有意改变 schema / 持久性 / 保留策略 / 权限且超出缺陷修复范围、使用付费服务或执行破坏性操作前，先询问用户。保留 FIFO 顺序、当前有效权限 / 完整性检查，以及可写操作的结算机制。
- 协议 / 版本升级、依赖补丁 / 覆盖 / 内置第三方代码、付费服务、版本发布和对外发布需要明确批准；修复 / 交付权限不等于版本发布权限。
- 基线 / 快照 / 忽略 / 预期失败例外：遵守[政策](.agents/skills/openclaw-testing/SKILL.md#baseline-and-expected-failure-exceptions)。
- `CODEOWNERS` 决定审查路由；受限 / 安全路径和重大变更需要列出的负责人参与（见[审查治理](.agents/skills/openclaw-pr-maintainer/SKILL.md#codeowners-review)）。
- 完成工作流的审查 / 合并关卡；解决实质性发现，或解释拒绝理由。宣告成功或清理前，验证远端结果；核对结果不确定的写入，绝不盲目重试。
- 仅暂存目标文件；使用简洁的 Conventional Commit 消息，并核实作者 / 编写者身份。保留贡献者署名；团队会话署名需要获得相关人类同意、核实身份，并附权威回链。单独一个 URL 不构成公开修改授权。持续更新 PR 正文中的问题、方案、影响和证据；对 shell 敏感的文本使用正文文件。
